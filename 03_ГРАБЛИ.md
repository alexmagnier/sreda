# Грабли — уже найдены и решены у автора

Формат: симптом → причина → что делать. Почти всё уже учтено в коде пакета. Этот файл нужен,
чтобы узнать проблему, если она всплывёт снова (другая версия Claude Code, LM Studio, модели).

## Модель и LM Studio

| Симптом | Причина | Что делать |
|---|---|---|
| Claude Code «думает» 2 минуты и падает, в логе LM Studio HTTP 500 «System message must be at the beginning» | шаблон Qwen не принимает `system` посреди диалога, а Claude Code его шлёт | патч шаблона (`02_ВЫБОР-МОДЕЛЕЙ.md`). Переменные `ANTHROPIC_DEFAULT_*_SUPPORTED_CAPABILITIES` для своего адреса **не работают** — проверено ловушкой запросов |
| Каждый шаг агента думает минутами | шаблон по умолчанию ставит рассуждение `xhigh`, а LM Studio умеет только «вкл/выкл» | тот же патч ставит `medium`. API-параметры `thinking: disabled` и `effort` MLX-модель игнорирует |
| Первый ответ ~30 с даже на «привет» | промпт Claude Code ~21K токенов: описания всех инструментов | в `config/policy-*.json` запрещены ненужные инструменты. Запрещённый инструмент не попадает в промпт: ~10,5K, ответ вдвое быстрее. **Не возвращать** |
| Лишние долгие запросы в фоне | подсказки промптов, сводки субагентов, «пока тебя не было» — каждый шлёт весь контекст | выключено переменными в лаунчере |
| GGUF-модель съела всю память при загрузке | llama.cpp резервирует кэш контекста целиком сразу | уменьшить `LAB_CTX`. MLX берёт память по мере надобности |
| Быстрее не стало от спекулятивного декодирования | `lms load --speculative-draft-mtp` грузится, но на 27B выигрыша нет (35 ток/с и так) | не тратить время |
| LM Studio сам скачал новый движок | `autoUpdateExtensionPacks` включён по умолчанию | выключить в `~/.lmstudio/settings.json` (фаза 2) |
| В `~/.lmstudio/server-logs/` фрагменты клиентских файлов | LM Studio пишет тела запросов в лог | лаунчер удаляет логи при каждом запуске, `claude-local --purge-logs` — вручную |
| Под тем же именем загружена не та модель | проверялось только имя | лаунчер проверяет ключ, контекст и «ровно одна модель в памяти» |
| Перекачал модель — снова HTTP 500 | новая загрузка затёрла пропатченный шаблон | повторить патч |
| `lms` молча не стартует сервер из VS Code | VS Code передаёт `ELECTRON_RUN_AS_NODE=1`, и LM Studio запускается как голый node | лаунчер снимает переменную. Если запускаешь сам из терминала VS Code — `env -u ELECTRON_RUN_AS_NODE` |
| Сервер виден в локальной сети | включено «Serve on Local Network» | выключить. Лаунчер отказывается работать, если порт слушает не только `127.0.0.1` |

## Харнесс и песочница

| Симптом | Причина | Что делать |
|---|---|---|
| «не та папка … слишком широкая или служебная» | открыта домашняя папка, корень проектов, `~/Library`, конфиги или сам харнесс | это защита: открыть конкретный проект |
| «клиентская папка. В Лаборатории … нельзя» | папка в `client-folders.list` | защита. Клиентские — только в «Локальный Claude» |
| Скиллы не читаются в режиме с интернетом (EPERM) | песочница закрывает `~/.claude` целиком | исправлено: исходники подключённых скиллов открыты точечно (тест есть) |
| Сообщение «от другой сессии» появилось в локальной сессии | Claude Code (2.1.22x+) открывает каждой сессии ящик для переписки — сокет в `CONF/tmp/cc-socks`, туда может написать любой процесс этого пользователя. Исходящие песочница закрывает, входящие — нет | в обеих политиках `"crossSessionInbound": "refuse"`, `ListAgents`/`SendMessage` в deny. Проверка — `tests/guard.test.sh`: настоящий Claude Code в каждой песочнице, внешний процесс пишет в ящик, сообщение должно быть отклонено. Без этого в Лабораторию с интернетом мог попасть текст из сессии с клиентскими файлами |
| Встроенная песочница Claude Code не включается офлайн | macOS запрещает вложенный `sandbox-exec` | её заменяет внешний профиль `config/offline.sb`. Так задумано |
| Модель предлагает `git clone`/`brew install`, а они не работают | песочница запрещает запись в `.git/config`, хуки, `.vscode`, всё вне рабочей папки | так задумано: это файлы, которые потом исполняются **вне** песочницы. Репозиторий — архивом через `curl`, программы ставит человек сам |
| Тесты песочницы «проходят», но ничего не проверяют | профиль не загрузился, и все запреты сработали по ошибке | в тестах сначала **положительный контроль** (разрешённое действие работает), потом запреты. Не удалять |
| Сломалось после обновления Claude Code | связка «Claude Code + не-Claude модель» официально не поддерживается | после `claude-local --pin-binary` — всегда `tests/verify.sh` и `tests/vscode-sdk-drive.py`. Не прошло — вернуть `~/.claude-local/bin/claude.prev` |
| В отчёте `verify.sh` «веб: поиск не дал результата» | DuckDuckGo иногда отдаёт капчу | повторить позже или ключ Brave Search API в `~/.claude-local-net/secrets/brave_api_key` |
| Веб-поиск Лаборатории не стартует | `node` из `~/.nvm` закрыт песочницей (домашняя папка) | node из Homebrew (`brew install node`), затем `./install.sh` ещё раз |
| Статус-строка не работает | путь к харнессу с пробелами | ставить в `~/local-ai/claude-local` (без пробелов) |
| zsh-скрипт ведёт себя странно после правки | переменные `path`/`fpath` в zsh связаны с `PATH` | не называть так переменные. В `local a=… b=$a` `$a` ещё пуст |
| `zsystem flock` «no such file» | flock не создаёт файл | сначала `: >> file` (в коде учтено) |
| Все тесты песочницы ❌ «sandbox_apply: Operation not permitted» | у Claude Code, который ставит пакет, включена своя песочница Bash, а вложенные песочницы macOS запрещает | эти команды запускать без песочницы установщика (с согласия человека) |
| `brew`/`uvx`/`claude-local`: command not found | свежий Homebrew и `~/.local/bin` не в PATH уже открытой сессии | `export PATH="/opt/homebrew/bin:$HOME/.local/bin:$PATH"` в начале каждой команды |
| `verify.sh --quick` ❌ «песочница не загрузилась», «LM Studio слушает сеть» с пустым адресом | сервер LM Studio не запущен (Mac перезагружали) | `~/.lmstudio/bin/lms server start --port 1234 --bind 127.0.0.1` и повторить |
| Модели скачаны, но `lms ls` их не видит | у LM Studio своя папка моделей (`downloadsFolder` в `~/.lmstudio/settings.json`) | качать туда, `check-hashes.sh` её учитывает |

## VS Code («Локальный Claude», «Лаборатория Claude»)

| Симптом | Причина | Что делать |
|---|---|---|
| Окно просит войти в Claude | обёртка не подхватилась | журнал `~/.claude-local/logs/vscode-wrapper.log`. Должны быть строки `kind=session … exec`. Нет строк — смотреть `claudeCode.claudeProcessWrapper` в настройках экземпляра |
| Чат ждёт минуту и перезапускается | расширение ждёт `initialize` ~60 с; загрузка модели дольше | модель грузится заранее (`--preload` при открытии окна). Всё долгое делать до открытия окна, не в обёртке |
| После обновления расширения чат не стартует | изменились аргументы, которыми расширение запускает Claude | `tests/vscode-sdk-drive.py` повторяет запуск как расширение и показывает, на чём упало. Фильтр аргументов — начало `bin/claude-local`, ветка `vscode` |
| Второе окно пишет «сейчас в памяти модель …» | в память помещается одна модель, первая занята открытым чатом | закрыть чат или окно другого режима. Так ответ в первом окне не оборвётся |
| Значок терминала включает облачный Claude | настройка «использовать терминал» | `claudeCode.useTerminal` в экземплярах принудительно выключен, а терминал внутри окна указывает на локальный `claude` |

## Островок

| Симптом | Причина | Что делать |
|---|---|---|
| В «Окнах» «Окно 1, 2, 3» вместо названий | нет разрешения «Универсальный доступ» | плашка «Разрешить» во вкладке «Окна». Запись экрана не нужна |
| Разрешение слетает после каждой пересборки | подпись ad-hoc: macOS привязывает разрешение к хешу программы | выдать заново или постоянная подпись (ниже) |
| Постоянная подпись: `codesign` «no identity found» | самоподписанный сертификат в отдельной связке ключей виден, только если связка в списке поиска | с согласия человека: `security list-keychains -d user -s ~/Library/Keychains/login.keychain-db <своя.keychain-db>`, затем `ISLAND_SIGN_IDENTITY=<хеш> ./scripts/install.sh`. Это изменение системы — только после «да» |
| В «Окнах» лишние невидимые окна | `CGWindowList` отдаёт служебные окна (у Safari 3 невидимых при 1 настоящем) | учтено: только приложения с иконкой в Dock, окна на каком-либо рабочем столе, проверка через Универсальный доступ |
| Окно на другом рабочем столе без названия | `kAXWindowsAttribute` видит только текущий стол | учтено: перебор id элементов (приём AltTab). Id растут всю жизнь приложения: лимит 40 000, поиск в фоне с бюджетом времени |
| Островок постоянно грузит процессор на 2–3% | SwiftUI `.glassEffect` на постоянно видимом элементе | пилюля на AppKit `NSGlassEffectView` (0,5%). Не возвращать SwiftUI-стекло |
| Агент «застрял», не может остановиться | хук на `Stop` вернул ненулевой код | команда хука всегда `… >/dev/null 2>&1 \|\| true` (в коде учтено) |
| Сборка островка: «package requires tools-version 6.2» | старые Command Line Tools после обновления macOS | `softwareupdate --list` → человек ставит свежие CLT |
| Отрисовка `--render` печатает `ROW` без названий | Универсальный доступ проверяется у программы, из которой запущена команда (VS Code, Терминал), а не у «Острова» | не ошибка; проверять глазами в самом островке после разрешения |
| Островок на macOS 15 не собирается | `NSGlassEffectView` и `.glassEffect` есть только в macOS 26 | адаптация: в `Package.swift` `platforms: [.macOS(.v15)]`, стекло заменить на `NSVisualEffectView` в `App/PanelController.swift` и на `.background(.ultraThinMaterial)` в SwiftUI. Автор на macOS 15 **не проверял** |
| Статусы агентов пустые | формат `~/.claude/sessions/<pid>.json` — внутренний у Claude Code и может меняться | сверить поля с `Services/SessionStore.swift` на текущей версии Claude Code |
| Экран зеркалируется на ТВ, а островок поверх фильма | при зеркалировании островок прячется сам; «Показать» в меню возвращает его | так задумано |
