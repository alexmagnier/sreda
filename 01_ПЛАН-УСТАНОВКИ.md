# План установки — для Claude Code

Десять фаз. Каждая заканчивается **гейтом**: условием, без которого дальше не идём. В начале
каждой фазы одной строкой скажи человеку, что сейчас делаешь. В конце — что получилось.

`$KIT` — папка этого пакета. `$H` — `~/local-ai/claude-local` (харнесс после копирования).
Каждый вызов Bash начинай с `export PATH="/opt/homebrew/bin:$HOME/.local/bin:$PATH"; H=~/local-ai/claude-local;`
(окружение между вызовами не сохраняется). Долгие команды — в фоне (правило 11 в `CLAUDE.md`).

   `code/island/hook/island-hook.py`, `code/island/Sources/Island/Services/*.swift`.

   ```bash
   cd "$KIT/code" && grep -rnE "https?://|curl |URLSession|fetch\(|NWConnection|socket" . | grep -v "^./claude-local/tests/eval/tasks.json"
   ```
   Ожидаемо и нормально:

4. Найди всё, что меняет систему: `grep -rnE "sudo|rm -rf|launchctl|/Applications|settings.json|zshrc" code`.
   Ожидаемо: свои папки и метки, LaunchAgent островка, ярлыки в `/Applications`, PATH-блок в
   `~/.zshrc` с метками `# >>> claude-local >>>`, хук островка в `~/.claude/settings.json` (с копией).
   `sudo` в коде нет и быть не должно.

## Фаза 1. Диагностика Mac и план

Собери факты одной пачкой команд:

```bash
uname -m; sysctl -n machdep.cpu.brand_string; echo "RAM $(( $(sysctl -n hw.memsize) / 1073741824 )) GB"
sw_vers -productVersion; df -h ~ | tail -1; pmset -g batt | head -2
command -v brew && brew --version | head -1
xcode-select -p 2>&1 && swift --version 2>&1 | head -1    # без CLT swift открыл бы окно установки
ls "/Applications/Visual Studio Code.app" >/dev/null 2>&1 && echo "VS Code: есть"
ls -d ~/.vscode/extensions/anthropic.claude-code-*-darwin-arm64 2>/dev/null | tail -1
ls -d "/Applications/LM Studio.app" ~/.lmstudio 2>/dev/null
for t in node uv; do for d in /opt/homebrew/bin /usr/local/bin; do [ -x $d/$t ] && echo "$t: $d/$t"; done; done
ls ~/.claude/skills 2>/dev/null
/usr/bin/python3 -c 'import json,os;print("LM Studio models folder:", json.load(open(os.path.expanduser("~/.lmstudio/settings.json"))).get("downloadsFolder") or "~/.lmstudio/models")' 2>/dev/null
grep -n '"sandbox"' ~/.claude/settings.json 2>/dev/null   # своя песочница Claude Code: см. правило 12
```

Реши по фактам:
- `uname -m` не `arm64` → пакет не подходит, объясни и остановись.
- Память → строка таблицы из `02_ВЫБОР-МОДЕЛЕЙ.md`. Меньше 16 ГБ — не ставим.
- Диск: свободно меньше 80 ГБ → предупреди, предложи только одну модель.
- macOS ниже 26 → островок только с адаптацией (`03_ГРАБЛИ.md`, «Островок на macOS 15»), спроси, нужен ли.
- Нет расширения Claude Code в `~/.vscode/extensions` (Claude Code только в терминале) → попроси
  поставить расширение в VS Code: без него `install.sh` остановится на закреплении бинаря.
- У LM Studio своя папка моделей (`downloadsFolder`) → дальше везде вместо `~/.lmstudio/models` используй её.

Задай человеку **одним сообщением** (с вариантами по умолчанию):
1. Что ставим: всё (по умолчанию) / только локальную модель / только лабораторию / только островок.
2. **Клиентские папки**: где лежат файлы клиентов и личные данные третьих лиц (абсолютные пути,
   можно несколько). Плюс личные заметки и vault, которые не должна читать сессия с интернетом.
3. **Корень проектов**: папка, где лежат все проекты сразу (например `~/Projects`). Целиком её
   открывать запрещено, только конкретный проект.
4. **Скиллы.** Покажи список из `~/.claude/skills` (имя и одна строка описания из `SKILL.md`)
   и предложи раскладку:
   - **офлайн** (`skills.list`): всё полезное для работы с файлами, включая клиентские;
   - **онлайн** (`skills-net.list`): только общие, без имён клиентов и чужих данных;
   - **не подключать**: скиллы, которым нужны облачные MCP (почта, диск, генераторы картинок и
     видео, CRM). Офлайн они не работают и только удлиняют каждый запрос.
5. Согласие на изменения системы: строка PATH в `~/.zshrc` (с копией); строка Homebrew в
   `~/.zprofile`, если ставим Homebrew; ярлыки в `/Applications`; хук островка в
   `~/.claude/settings.json` (с копией); автозапуск островка (LaunchAgent); остальное — таблица
   «Где что будет установлено» в `CLAUDE.md`.
6. Mac сейчас на зарядке? Загрузка и тесты моделей — только от сети.

Покажи план: что ставим, какие модели (с размерами), сколько места (≈ сумма моделей + 20 ГБ),
сколько времени (загрузка 40 ГБ на 100 Мбит/с ≈ 1 час; всё вместе 1,5–3 часа).

**Гейт 1:** человек ответил на вопросы и сказал «да» плану.

## Фаза 2. Зависимости

Нет Homebrew → дай человеку команду с https://brew.sh (её нужно выполнить в его терминале,
она спросит пароль). Установщик в конце печатает строку для `~/.zprofile` — пусть человек выполнит
и её. В твоих командах Homebrew доступен через `export PATH="/opt/homebrew/bin:$PATH"`. Дальше:

```bash
brew install --cask lm-studio         # официальный cask; Developer ID Element Labs
brew install node uv                  # node — для веб-поиска Лаборатории; uv — для hf и gguf
```
Нет Xcode Command Line Tools (нужны для островка) → `xcode-select --install` (откроется окно,
человек нажимает «Установить»). Есть, но Swift ниже 6.2 (`swift --version`; бывает после
обновления macOS) → `softwareupdate --list | grep -i "Command Line"`, и человек ставит найденное:
`softwareupdate -i "<название>"`. Нет VS Code или расширения Claude Code → попроси поставить
(VS Code с code.visualstudio.com, расширение Claude Code от Anthropic из Marketplace).

Проверь подлинность LM Studio:
```bash
codesign --verify --deep --strict "/Applications/LM Studio.app" && spctl -a -vv "/Applications/LM Studio.app" 2>&1 | head -3
# ожидается: accepted, Notarized Developer ID, Element Labs Inc (D65G88RHWN)
```

Первый запуск LM Studio (предупреди: откроется окно) создаёт `~/.lmstudio` и CLI `~/.lmstudio/bin/lms`.
Закрой LM Studio и выключи самообновление движков и автозагрузку встроенной модели (с копией):
```bash
cp ~/.lmstudio/settings.json ~/.lmstudio/settings.json.bak-$(date +%Y%m%d-%H%M)
/usr/bin/python3 -I - <<'PY'
import json, os
p = os.path.expanduser("~/.lmstudio/settings.json"); s = json.load(open(p))
s.setdefault("developer", {})["autoUpdateExtensionPacks"] = False
s["autoLoadBundledLLM"] = False
json.dump(s, open(p, "w"), indent=2)
PY
```
Запусти сервер только на этом компьютере и проверь:
```bash
~/.lmstudio/bin/lms server start --port 1234 --bind 127.0.0.1
lsof -nP -iTCP:1234 -sTCP:LISTEN     # адрес только 127.0.0.1, НЕ *:1234
```

**Гейт 2:** `lms version` отвечает, сервер слушает только `127.0.0.1:1234`, подпись LM Studio валидна.

## Фаза 8. Островок

Нужны macOS 26 и Xcode Command Line Tools со Swift 6.2+ (`swift --version`).
```bash
rsync -a "$KIT/code/island/" ~/local-ai/island/
cd ~/local-ai/island && python3 -I hook/test_island_hook.py && ./scripts/install.sh
```
`install.sh` собирает приложение в `~/Library/Caches/island-build`, ставит `/Applications/Остров.app`,
автозапуск (LaunchAgent `local.claude-kit.island`) и хук статусов «ждёт тебя» в `~/.claude/settings.json`.
Хук ставит `install_hook.py`: он делает копию `settings.json.bak-island-*` и меняет только свои записи.

Проверка без окон на экране — отрисовка вкладки «Окна» с реальными окнами в картинку:
```bash
ISLAND_RENDER_REAL=1 "$(cd ~/local-ai/island && swift build -c release --scratch-path ~/Library/Caches/island-build --show-bin-path)/Island" --render /tmp/island.png
```
Открой `/tmp/island-windows.png` и посмотри. Скрипт печатает строки `ROW …`. Названия окон,
папки и вкладки видны, только если у программы, **из которой ты запускаешь команду** (VS Code или
Терминал), есть Универсальный доступ. Нет — строки будут без названий, это не ошибка островка.
Главная проверка — глазами человека после того, как он даст разрешение «Острову».

Человеку: островок над нотчем, вкладка «Окна» → «Разрешить» → включить «Остров» в
Системных настройках → Универсальный доступ. Это единственное нужное разрешение.

**Гейт 8:** островок виден, вкладка «Агенты» показывает текущую сессию Claude Code, вкладка
«Система» — память и LM Studio, после разрешения «Окна» показывают папки и вкладки.
