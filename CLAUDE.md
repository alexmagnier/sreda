# Пакет «СРЕДА»: инструкция для Claude Code, который это устанавливает

Ты — Claude Code на компьютере пользователя. Человек открыл эту папку и хочет получить у себя
то же, что собрано у автора пакета:

1. **Локальная модель в привычном Claude Code.** Тот же чат в VS Code, те же скиллы, но «мозг» —
   открытая модель в LM Studio на этом Mac. Режим **без интернета** для клиентских файлов: сеть
   закрыта песочницей ядра macOS.
2. **Лаборатория.** Модель без фильтров (abliterated) с поиском в интернете — для своих устройств
   и экспериментов.
3. **Островок над нотчем.** Статусы агентов Claude Code, окна по рабочим столам (папки VS Code,
   вкладки Safari), память, процессор, выгрузка модели.

Код готов и проверен у автора: `code/claude-local/` (харнесс) и `code/island/` (островок).
Твоя работа — **проверить код, подстроить под этот Mac и этого человека, установить и доказать
тестами, что работает.** С нуля ничего не пиши: все известные грабли уже решены в коде и описаны
в `03_ГРАБЛИ.md`.

## Порядок работы

Иди строго по `01_ПЛАН-УСТАНОВКИ.md`, фаза за фазой. В конце каждой фазы есть «Гейт»: пока он
не пройден, к следующей фазе не переходи. Модели выбирай по `02_ВЫБОР-МОДЕЛЕЙ.md`. Приёмка —
`04_ПРИЁМКА.md`. Объяснение для человека, как всё устроено, — `05_КАК-ЭТО-УСТРОЕНО.md`.

## Жёсткие правила

1. **Сначала план и согласие.** После диагностики (фаза 1) покажи человеку одним сообщением:
   что поставишь, сколько займёт места и времени, что изменишь в системе. Все вопросы задай
   **одним списком**. Без «да» ничего не ставь.
2. **sudo никогда не запускай сам.** Нужны права администратора (Homebrew, Xcode Command Line
   Tools) — дай человеку точную команду, он выполнит её в своём терминале.
3. **Код пакета — чужой код для этого компьютера.** Перед установкой прочитай его и проверь
   (фаза 0). Нашёл что-то, что шлёт данные наружу или делает не то, что описано, — остановись
   и покажи человеку.
4. **Клиентских данных пользователя не открывай.** Для настройки достаточно путей к папкам.
   Тесты используют собственные папки-приманки, а не реальные.
5. **Тяжёлое — только от сети.** Загрузка модели и генерация тратят 60–100 Вт. Перед любым
   прогоном модели проверь `pmset -g batt`. На батарее — спроси, прогоны короткие. У автора
   серия тестов посадила батарею с 80% до 10% за полчаса.
6. **Окна и диалоги на экране — только с предупреждением.** Перед действием, которое откроет
   окно (VS Code, LM Studio, Системные настройки), скажи об этом одной строкой.
7. **Резервная копия перед правкой чужого файла.** `~/.zshrc`, `~/.claude/settings.json`: сначала
   копия рядом с датой, потом правка. Правки — только свои, с метками.
8. **Не выдумывай названия моделей и версии.** Всё, чего нет в пакете, проверяй на месте:
   каталог Hugging Face, `lms ls`, `--help`, `--version`.
9. **Отчёт честный.** Не прошёл тест — так и пиши, с выводом. Шаг пропущен — тоже пиши.
10. **PATH в каждой команде.** Окружение Bash не сохраняется между вызовами, а свежий Homebrew и
    `~/.local/bin` в PATH твоей сессии не попадут. Начинай каждый вызов с
    `export PATH="/opt/homebrew/bin:$HOME/.local/bin:$PATH";` или пиши полные пути (`$H/bin/claude-local`).
11. **Долгое — в фоне.** Загрузка моделей (до часа), `check-hashes.sh` (хеши 40 ГБ), полный
    `verify.sh` (5–8 мин), экзамен моделей, первая сборка островка дольше лимита одного вызова Bash
    (10 мин). Запускай их в фоне и проверяй результат по завершении.
12. **Твоя собственная песочница.** Тесты пакета сами запускают `sandbox-exec`, а macOS запрещает
    вложенные песочницы. Если у Claude Code, который ставит пакет, включена песочница Bash
    (`sandbox` в `~/.claude/settings.json`), эти команды придётся запускать без неё. Спроси человека.

## Требования (проверяются в фазе 1)

- Mac на Apple Silicon (M1 и новее). На Intel и Windows пакет не рассчитан — честно скажи и остановись.
- Память от 16 ГБ, комфортно от 32 ГБ. Таблица — в `02_ВЫБОР-МОДЕЛЕЙ.md`.
- Свободно на диске от 80 ГБ (две модели плюс копия с исправленным шаблоном).
- VS Code с расширением Claude Code. Харнесс берёт подписанный бинарь Claude Code из расширения.
- Homebrew. Для островка — Xcode Command Line Tools и macOS 26 (на macOS 15 островок нужно
  адаптировать, см. `03_ГРАБЛИ.md`).

## Где что будет установлено

| Что | Куда |
|---|---|
| Харнесс (копия `code/claude-local`) | `~/local-ai/claude-local` (путь без пробелов) |
| Островок (копия `code/island`) | исходники в `~/local-ai/island`, приложение `/Applications/Остров.app` |
| Конфиги и история локальных сессий | `~/.claude-local` (без интернета), `~/.claude-local-net` (с интернетом) |
| Модели | `~/.lmstudio/models/…`, оригинал исправленной модели — `~/.lmstudio/originals/…` |
| Команды | `~/.local/bin/claude-local`, `claude-lab`, `local-vscode` |
| Программы | `/Applications/Локальный Claude.app`, `/Applications/Лаборатория Claude.app` |
| Отдельные экземпляры VS Code | `~/Library/Application Support/claude-local-vscode/{work,lab}` |
| Папка Лаборатории по умолчанию | `~/Лаборатория` |
| Кэш прогрева, сборка островка, состояние хука | `~/.cache/claude-local-warm`, `~/Library/Caches/island-build`, `~/.claude-island` |
| Правки чужих файлов (с копией) | `~/.zshrc` — блок PATH с метками; `~/.claude/settings.json` — хук островка; `~/.zprofile` — строка Homebrew, если ставим Homebrew |

Тесты на время прогона перезаписывают буфер обмена (проверяют, что песочница его не читает).
Предупреди об этом.

Почему копия, а не эта папка: эту папку человек мог положить в синхронизируемое место (iCloud,
Загрузки). Харнесс должен жить там, где его не переписывает синхронизация и где путь не изменится.
